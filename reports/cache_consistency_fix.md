# OCR 与 YOLO 缓存一致性修复

V4.1 开发过程中发现，同一案例在独立 dev30 与全量 150 运行中的 RapidOCR token 数不同。追踪后确认，旧缓存键写死了 `rapidocr-1.4.4`，但没有读取实际安装版本；YOLO 缓存也只使用权重文件大小，理论上两个同大小权重可能误用同一缓存。

已完成以下修复：

1. RapidOCR 缓存键加入实际包版本、检测尺寸、分类开关和 V4.1 配置版本。
2. 局部识别与 pin 识别使用独立版本化缓存键。
3. YOLO 缓存键由文件大小改为完整权重 SHA256 与推理配置。
4. RapidOCR 1.4.4 以项目内隔离运行时加载，不覆盖用户 Conda 环境；Python 3.14 已完成真实案例兼容测试。
5. 最终 150 例使用新缓存目录重新生成，旧运行仅保留为审计证据。

这项修复不改变评分算法，但保证后续 A/B 的差异来自代码和模型，而不是历史缓存。`OFFICIAL_SCORE = FALSE`。
