# 引脚 V4 与诊断评测：同条件开发集对比

## 实验边界

- 分支：`feature/modular-baseline`；本轮基于当前分支重新生成 V3 基线。
- 数据：仅 `200_train_cases/0001` 至 `0150`，未使用 `0151～0200` 或 `10_GTcase`。
- 不训练新模型。器件模型、OCR 文字、器件框、类型、值、名称固定；导线与拓扑均固定为 V3，只替换引脚定位/语义两个模块。
- `evaluate_v2.py` 保持不变。严格分数与新增诊断分数分别报告，不把改变评分口径算成算法提升。
- 全部是开发集、本地非官方评测，不代表保留验证集或官方成绩。
- 旧的未提交 nets V4 与其运行证据不在恢复后的目录中；本次数字不与旧 nets V4 历史数字直接作差。

## 本轮落地内容

1. `evaluate_diagnostic.py`：标识/名称忽略大小写；只有答案明确未标编号的器件才豁免自动编号差异；保留值的大小写含义（如 `m` 与 `M`）。另有完全独立的位置/连通诊断。
2. 引脚语义 V4：局部方向、距离和行间距约束；同一实际 OCR 文字只归属于一个器件；同器件内编号唯一；框内 `A1/P12` 等作为信号名称候选；框外 BGA 编号仍可用。
3. 引脚定位 V4：保留 V3 候选，只在连续像素支持短引线端点或单一 L 角时修正坐标。断点、分叉、文字遮挡、搜索/图片边界以及长连续导线均回退。双端器件、四脚晶振及 GND 维持既有几何。
4. 未知引脚保留在内部 `scene.json`，不猜测物理编号。单独重建的 `internal_connectivity.json` 只用于几何诊断，不能替换正式 `result.json`。

## 证据与复现

- 图像推理冻结快照及基线：`runs/pins_v3_prepare/report.json`。
- 冻结算法后的完整配对：`runs/pins_v4_full/report.json`。
- 固定的 10 例校准子集：`0001,0002,0003,0004,0006,0007,0008,0009,0011,0012`；最终小样本记录在 `runs/pins_v4_calibration_final/report.json`。这些例子属于上述 150 例，不是额外验证集。
- 所有案例先推理、后读取答案评分；缓存含图片、源文件、模型和内容校验信息。源代码与逐例匹配、错误分项均可追溯。
- 回归测试：137 项通过，包括 11 项合成像素定位测试、23 项引脚语义测试、22 项诊断评测测试。
- 主程序模块化入口的 `0001` 输出通过正式结构校验，并与配对工具的候选输出完全一致，证据目录 `runs/pins_v4_entry_smoke/0001/`。
- 完整命令、模块职责与四种口径边界见 `docs/PINS_V4.md`。

## 最终结果

150/150 例完成，失败 0 例。300 份正式输出均通过结构校验；150 例的器件/OCR 未改变，重跑基线逐例与准备阶段完全一致，评测结束时源文件哈希仍与启动时一致。

**结论：网络集合指标小幅上升，但引脚与引脚对指标下降，不能称为全面或稳定提升。`configs/current.json` 未改；V4 仅作为显式选择的实验配置保留。**

### 原严格口径：逐例平均 F1

先分别计算每例 F1，再对 150 例等权平均。百分数为 F1，差值为百分点。

| 指标 | V3 基线 | V4 候选 | 变化 |
|---|---:|---:|---:|
| Component：器件 | 36.2679% | 36.2679% | 0.0000 |
| Pin：引脚编号、名称与位置 | 17.5140% | 17.3245% | -0.1895 |
| NetHypergraph：网络成员集合 | 15.7866% | 16.0548% | +0.2682 |
| NetLine：连线几何 | 3.0018% | 3.0385% | +0.0367 |
| PinPair：引脚两两连通 | 1.8080% | 1.7585% | -0.0495 |

原评测器的逐例平均加权 FinalScore 为 21.0843 → 21.1345（满分 100），仅增加 0.0502；它不是全部引脚或全部网络都正确的比例。

### 原严格口径：合并计数 F1

先合并所有案例的正确数、预测数、答案数，再算 F1。器件数较多的案例影响更大，不能与上表混用。

| 指标 | 正确数 V3→V4 | 预测数 V3→V4 | 答案数 | 合并 F1 V3→V4 |
|---|---:|---:|---:|---:|
| Component | 2095→2095 | 5679→5679 | 6080 | 35.6323%→35.6323% |
| Pin | 1844→1847 | 5871→6093 | 14817 | 17.8268%→17.6662% |
| NetHypergraph | 1660→1728 | 5871→6093 | 14720 | 16.1235%→16.6050% |
| NetLine | 942→938 | 32502→32432 | 22174 | 3.4458%→3.4355% |
| PinPair | 226→238 | 4633→6008 | 14957 | 2.3073%→2.2705% |

其中严格 Pin Precision 为 31.4086% → 30.3135%，Recall 为 12.4452% → 12.4654%。正确引脚只净增加 3 个，而输出净增加 222 个，因此精确率与 F1 下降。NetLine 的逐例平均 F1 略升，但合并 F1 略降，也不能笼统称为改善。

### 按用户要求规范化身份后的诊断口径

标识与名称忽略大小写；仅答案明确未标编号时豁免自动编号差异。它仍考查真实编号、引脚名称与坐标，不是纯位置匹配。

| 指标 | 逐例平均 F1 V3→V4 | 变化（百分点） | 合并 F1 V3→V4 |
|---|---:|---:|---:|
| Component | 44.6594%→44.6594% | 0.0000 | 45.4971%→45.4971% |
| Pin | 17.5590%→17.3668% | -0.1922 | 17.8751%→17.7140% |
| NetHypergraph | 15.8733%→16.1359% | +0.2626 | 16.2110%→16.6915% |
| NetLine | 3.0397%→3.0762% | +0.0365 | 3.4970%→3.4868% |
| PinPair | 1.8080%→1.7585% | -0.0495 | 2.3073%→2.2705% |

例如，同一版本的器件逐例平均 F1 从严格口径 36.2679% 变为诊断口径 44.6594%，**只是评分口径差异**；本轮没有改变器件识别算法，也没有让器件识别提升 8.3916 个百分点。

| 预测范围与指标 | 逐例平均 F1 V3→V4 | 合并 F1 V3→V4 |
|---|---:|---:|
| 正式导出引脚：Pin 几何 | 37.6600%→38.3984% | 35.4698%→35.9732% |
| 正式导出引脚：NetHypergraph 几何 | 26.5394%→26.7371% | 25.2440%→25.5417% |
| 正式导出引脚：PinPair 几何 | 5.2857%→5.3913% | 7.4732%→7.7749% |
| 保留全部内部引脚：Pin 几何 | 45.5810%→45.5941% | 42.2280%→42.2202% |
| 保留全部内部引脚：NetHypergraph 几何 | 30.4441%→30.4465% | 29.5223%→29.5223% |

两边均保留 10820 个内部候选。V4 有 4727 个未知编号候选未作为正式编号导出。定位规则移动了 289 个端点（208 个短端点、81 个 L 角），但全部内部候选的位置正确数为 **5413→5412**，没有整体净收益。正式导出引脚的几何正确数增加，主要来自选择了不同的可导出候选，不能全部归功于坐标更准。

## 为什么没有全面提升

逐个对齐同一器件、同一候选序号，并核验基点/方向不变后：

- 新增导出 734 个，取消导出 512 个，始终导出 5359 个，净增 222 个。取消导出不等于删除内部候选。
- 新增 734 个中，525 个所在器件在身份规范化口径下仍无法匹配。这些引脚即使位置正确，也不能自动补救器件编号错误。
- 新增中 203 个有几何匹配；其中 42 个编号与几何匹配答案后缀相同、161 个不同。编号不同可能还涉及答案内部编号口径，不能全部断言为 OCR 字符识错。
- 新增中 531 个无几何匹配：120 个连器件类型/框都未匹配；411 个器件匹配，但引脚未满足 5 像素位置容差。这里“未匹配”不是对错误原因的唯一判定。
- 取消导出的 512 个中，原有 111 个几何匹配。始终导出的候选，几何命中状态未增减。因此正式几何正确数的净增 92，恰好等于新增 203 减去取消 111。

| 新增候选所在器件的身份匹配 | 引脚几何匹配 | 数量 |
|---|---|---:|
| 有 | 有 | 41 |
| 有 | 无 | 168 |
| 无 | 有 | 162 |
| 无 | 无 | 363 |

固定的器件前端仍有明显瓶颈：4785 个类型与框已匹配的器件中，1519 个可见位号不符；类型/框匹配对中有 881 处值不符、556 处芯片 Name 不符。另有 1295 个答案器件未得到类型＋框匹配。分类允许重叠，不能直接相加当作独立错误总数，也不能据此把全部问题归因于某一个模型。

## 交付与建议

诊断评测、引脚 V4 实验实现、回归测试、完整配对报告及复现说明均已落地。未更改默认配置、未提交 Git、未训练或下载新模型，也未读取保留验证集。

下一轮建议先处理“器件可见位号/芯片型号与正确框的关联”，再针对真实引脚端点做更有力的定位方案。单独放宽数字候选会增加输出量，但本轮证据表明它不足以带来可靠的端到端收益。不应根据这次开发集小幅网络增长就直接替换默认算法。
